00 · Normalization

Twelve decisions that end the drift

The mockups were drawn in three passes and disagree with each other. Where they disagree, this column wins — the mockup is wrong, not the spec. Nothing below is a preference; each one removes a duplicate way of doing the same thing.

SubjectDrift in the mockupsDecision
AccentSACDA orange #F99D2A in groups D–F, amber app-chrome tokens in A–COne accent, from the theme: primary — #1a73e8 light, #3c78d8 dark. Orange appears nowhere in the app.
TypeSegoe UI and ui-monospace in D–FArchivo and IBM Plex Mono only, bundled in assets/fonts/. The mockup stacks were placeholders.
Title bar34px in A, 36px and 40px in B and E34px, every window, padding 0 12.
Sidebar168px in the builder, 186px in settings176px in both. The search field is an optional first slot, not a different sidebar.
Control height6px and 7px vertical padding used interchangeably30px tall, padding 7 10. Small variant 26px, padding 0 10. Nothing else.
Radius3, 4, 6 and 8 all present3 nav item / tag / chip, 4 control / card, 6 window / dialog / popover, 999 switch. No 8.
Label column180px in settings, 210px in the builder180px, gap 14. Long keys wrap to two lines; the column does not grow.
Inline actionsBare text — Edit, Test, Duplicate, Switch to, Manage profilesAll become GhostButton, 26px, with a hover surface. No unbordered clickable text anywhere except a real hyperlink.
Status dotsAccent used for "reachable" and for "active profile"Dots are semantic only: success / danger / warning / muted_foreground. Accent means action or selection, never health.
ValidationSometimes inline, sometimes a colored row backgroundAlways a message under the control, 5px gap, 11px mono glyph in a fixed 14px column. Row backgrounds never carry error state.
ZebraApplied to setting rows in one mockupZebra (table_even) lives in RowEditor tables only. Setting rows are separated by a 1px rule.
Type badge60px right column in the builder, absent in settingsKept, at 56px, right-aligned, faint — builder only. It is the one legitimate difference between the two windows.

Order. Theme JSON, then fields/row.rs and message.rs — every other field renders inside them. Then the simple fields (text, path, url, char, number), then row_editor.rs, which is the largest single piece and unblocks five value shapes. Then shell/, which lets both windows exist. SettingPicker, YamlPreview and EntityCard next. task_chain.rs last — it depends on the config library being real.

Two invariants for review. No component reads a literal color: every surface, border and text color comes from cx.theme().colors.*. No component sets its own height: heights are 26, 30, 34 and nothing else, taken from the constants in theme.rs. A patch that adds a fifth height or a fourth radius should be sent back.
