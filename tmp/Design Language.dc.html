01 · How to read this

Three rules that decide everything else

The theme is data, not code. gpui-component loads themes from JSON against its own schema (theme/schema.rs, theme/default-theme.json). Ship our palettes as files under assets/themes/ and register them with the ThemeRegistry. Never hard-code a color in a component; read cx.theme().colors.*.

The settings module already is the config builder. crates/ui/src/setting/ gives us SettingsPage → SettingGroup → SettingItem → SettingField, with built-in label/description layout, a per-item reset affordance driven by default_value, and an escape hatch (SettingField::render) for any control it does not ship. Every one of our 16 YAML value shapes is a SettingField. We add controls, not layout.

Build only what the vocabulary demands. Four widgets have no upstream equivalent: the setting picker, the key/value table, the YAML preview, and the task-chain tree editor. Everything else on screen is upstream with a thin wrapper.

03 · Type

Two families, six sizes, three weights

Archivo for prose and labels, IBM Plex Mono for anything that is literally YAML, a path, a key, a command, or a numeric value the user will compare digit by digit. The rule is not decorative: monospace signals "this text is data the tool will parse."

Theme fields. font_family: "Archivo", font_size: px(12.5), mono_font_family: "IBM Plex Mono", mono_font_size: px(12.5). Bundle both families in assets/fonts/ and load them at startup — do not rely on the OS having them. Fallback chain: Archivo → Inter → system-ui; Plex Mono → Consolas → ui-monospace. Weights: 400 body, 500 active nav and mono labels, 600 headings. Nothing is bold; nothing is italic.

Truncation. Paths and URLs truncate at the head, not the tail (…/scripts/preprocess.py), because the distinguishing part is at the end. Everything else truncates at the tail with a tooltip carrying the full value.

04 · Space, radius, stroke

4px grid, one dense scale

This is a desktop tool that shows 140 settings; density is a feature. The scale below is deliberately tighter than a web app's — the largest gap in a settings pane is 18px.

Stroke and elevation

Every border is exactly 1px border. There is no 2px border anywhere except the focus ring and the drag target. Two shadows only: 0 10px 30px rgba(23,20,15,.15) for floating windows and dialogs, 0 4px 12px rgba(23,20,15,.12) for popovers and dropdowns. Cards, rows, and inputs are flat — separation comes from the 1px rule and the surface step, never from a shadow.

Motion. 120ms for state color changes, 160ms for popover and dropdown entry, 200ms for panel dock/undock. Ease-out. No spring, no bounce, no animated skeleton beyond the upstream shimmer during a workbench run.

09 · The four widgets we write

Anatomy of the custom pieces

SettingPicker — the search-to-add popover

Built on searchable_list plus popover; do not hand-roll the filtering or the virtualized list. Panel 420×360, radius 6, popover shadow. Search input pinned at the top, 30px, no border, 1px rule beneath. Results are 34px rows: mono key name left, category tag right in muted_foreground, one-line description underneath at 11.5px when the row is highlighted. Group headers are 11px mono caps, sticky. Keys already present in the config appear disabled with a mono "added" tag. Enter adds and keeps the panel open; Esc closes; the counter in the footer reads "142 settings · 12 in this config".

MapEditor / ListEditor / PairListEditor — one family

All three are the same shell: a bordered box, radius 4, header row at table_head when there are named columns, 30px rows separated by 1px table_row_border, and a dashed Add-row strip as the last child. Cells are mono inputs that look borderless until focused. A 22px trailing column holds the remove glyph, visible on row hover only. Drag handles occupy a 16px leading column and appear on hover. Differences are only in the cell count and the parse function, so implement one generic RowEditor with a column spec.

YamlPreview

Read-only highlighter with a YAML grammar, 11.5/1.6 mono, no line numbers under 40 lines. It is the source of truth for what will be written: it re-renders on every keystroke, and a validation message links to its line. Panel background is background, not a darker code well — this is not a code editor and should not pretend to be.

TaskChainTree

Upstream tree for the hierarchy, plus a horizontal run-order strip above it: numbered mono chips, 26px tall, with a chevron between them, showing the flattened depth-first order. A reference that would create a cycle is refused at drop time with the offending edge drawn in danger for 800ms rather than a dialog.

10 · Handoff

File layout and order of work

assets/ fonts/ Archivo, IBM Plex Mono (bundled, not system) themes/ qrate-light.json, qrate-dark.json, gruvbox-*.json, everforest-*.json crates/app/src/ theme.rs register themes with ThemeRegistry; persist choice in settings fields/ mod.rs re-exports; the SettingField extension trait path.rs PathField (wrap) url.rs UrlField (wrap) char.rs CharField (build) enums.rs segmented + nullable dropdown (wrap) row_editor.rs RowEditor + column spec -> List/Map/Pair/Command editors (build) template.rs ${...} highlight + resolved preview (wrap) widgets/ setting_picker.rs searchable_list + popover (wrap) yaml_preview.rs highlighter, read-only (wrap) task_chain.rs tree + run-order strip (build) config_builder/ SettingsPage assembled from the schema app_settings/ existing settings window, ported onto setting::SettingsPage

Build in this order: theme JSON first, then the generic RowEditor, then the four wrap-level fields (path, URL, enum, nullable enum), then SettingPicker, then the tree. The settings window and the config builder both fall out of setting::SettingsPage once the field set exists, so do not build either screen until the fields are done.

Two things this spec does not decide. Whether the config library is stored per profile or per machine, and whether a preprocess script must declare anything beyond writing metadata.csv. Both change what ConfigRefPicker and the script dropdown read from, so settle them before those two widgets.
